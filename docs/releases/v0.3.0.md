# v0.3.0 — MMD integration checkpoint

> Candidate scope, not a published release. No release date or tag is asserted.
> Finalize this record only after the release gates below pass.

## Summary

An integration checkpoint on top of [v0.2.0](v0.2.0.md): MMD control/coupling
APIs and bounded owner/runtime/renderer evidence, with installed packaging
verification. PMX import, the material schema/imaging interface, shared-motion
adapters and USDZ export already shipped in v0.2.0; they are the baseline,
not new features of this candidate. The
[capability matrix](../reference/CAPABILITY_MATRIX.md) owns current support.

## Candidate changes and existing evidence

These changes are present after v0.2.0. Dated reports prove only their stated
fixtures, environments and package compositions; they do not certify new
release artifacts or published downstream dependencies.

- Owner control continuation (`BeginPhysics` / `ResumePhysics`), non-bone
  group resolution, UV deltas and material modulation, with generated unit
  and installed-consumer coverage. See the
  [control contract](../design/MOTION_CONTRACT.md#11-evaluating-the-control-rig)
  and [morph evidence index](../reports/README.md#live-input-morphs-and-pose-feedback).
- Optional `mmdPhysicsAdapter`: bone/body coupling, strict and explicit
  source-policy readers, joint spring audit and inert-joint classification.
  The [admission evidence](../reports/2026-10-31-phase8-inert-joint-admission.md)
  and [source-damping execution](../reports/2026-10-31-phase8-source-damping-runtime.md)
  retain the installed-package scope. Independent experimental spring opt-ins
  remain bounded approximations, not Bullet equivalence.
- Generated owner → runtime → resident renderer integration combining skin,
  vertex morph, primary UV, physics feedback and canonical materials. The
  [combined parity report](../reports/2026-10-31-phase8-combined-render-parity.md)
  compares streams and pixels with sampled-tint realization OFF. The separate
  [live-material report](../reports/2026-10-31-phase8-live-material-integration.md)
  covers sampled-tint GPU reference checks; it is not sampled-tint Hydra/direct
  parity or representative private-asset acceptance.
- [Scoped native viewport review](../reports/2026-10-31-phase8-native-viewport-admission.md)
  of one original private PMX/VMD pair with user-confirmed visible output.
  Its local package composition and below-realtime performance bound the claim;
  the review does not assert every control or the entire motion was exercised.
- Per-platform bundle/tool GHCR publication and digest pin-table generation
  in the [release workflow](../../.github/workflows/release.yml). Publication
  and new digests require the release dry run and subsequent tag run.

## Compatibility and stage-contract version

The authored stage remains **stage-contract 2**. This documentation cleanup
does not change schema, authored values or stage interpretation. A package
version bump does not itself change that contract.

Before cutting the candidate, set [VERSION](../../VERSION) and all required
manifest mirrors to the candidate version, including sibling ranges and
installed-consumer requests. The tree retains its pre-candidate package version
until that coordinated release-preparation change. `SameMinorVersion` means
consumers requesting the old minor must update their `find_package` requests
and rebuild; additive APIs alone do not prove binary interchangeability.

OpenUSD identity, external motion pins and physics descriptor/build/ABI
requirements remain owned by [DEPENDENCIES](../architecture/DEPENDENCIES.md)
and its linked manifests. Check exported APIs, plugin dependencies and clean
installed-consumer resolution against the actual candidate artifacts.

## Known limitations and explicit non-claims

- P1-C/P1-2/P1-3 stay open: no complete application lifecycle, licensed fixed
  representative L3 suite, arbitrary-model fidelity or unrestricted admission.
- Generated canonical material parity with tint OFF, sampled-tint GPU checks
  and scoped private visual review are distinct evidence. Private Hydra/direct
  parity, representative material appearance and additional runtime UV output
  remain unaccepted.
- Opt-in, approximated physics reader/replay coverage does not establish
  Bullet trajectories, native MMD parity or arbitrary-model hair/skirt/contact
  fidelity. The importer stays static and physics-free.
- Existing Local Append and SDEF approximations, QDEF uncertainty and missing
  MMD-output IK comparison retain the [matrix](../reference/CAPABILITY_MATRIX.md)
  qualifiers. The scoped private preview is below real time; production realtime
  performance and final combined interactive acceptance remain unclaimed.

## Integration ownership and downstream requirements

MMD owns source semantics, control/coupling and participant data. Generic
physics belongs to `usd-physics-plugins`, avatar orchestration/world barriers
to `usd-avatar-runtime`, host ticks to `usd-stage-runner`, and resident/GPU
realization to `hydra-toon`. Local rebuilt compositions do not imply published
dependencies or inclusion of those applications in this bundle/tool product.
`mmdPhysicsAdapter` is a separately installable source library, not an aggregate
product member. Each repository can release bounded evidence independently,
without binding this candidate to an unpublished neighboring release.

Remaining MMD-local outcomes are in [current.md](../roadmap/current.md),
and optional work is in [backlog.md](../roadmap/backlog.md).

## Upgrade notes from v0.2.0

Keep stage-contract 2 material readers. Rebuild CMake consumers against the
new minor and verified installed dependency closure when the package version
advances. Runtime/renderer execution requires explicit consumer composition;
importing or exporting a PMX does not start it. Release verification must check
the [opening](../guides/opening.md), [inspection](../guides/inspecting.md) and
[export](../guides/exporting.md) entry points against installed tools.
