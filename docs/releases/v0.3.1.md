# v0.3.1 — pinnable libraries for C++ consumers

**Date:** 2026-11-01 ·
[Release page and final run identities](https://github.com/animu-sphere/usd-mmd-plugins/releases/tag/v0.3.1)

## Summary

Lets another repository build against the MMD control and coupling libraries by
digest. `usd-avatar-runtime` needs this for its
[MMD session package](https://github.com/animu-sphere/usd-avatar-runtime/blob/main/docs/architecture/MMD_SESSION.md#package-boundary).

## What ships

- `mmdPhysicsAdapter` and what it requires, `mmdControl`, `mmdMotionBinding`, `mmdModel`,
  `mmdPmx` and `motionVmd`, as release assets and GHCR packages on Windows, Linux and
  macOS, in the pin table under `libraries`.
- Every bundle, tool and the product, rebuilt at this version. No source changes.

`mmdMotionAdapter` and `mmdSkeletonAdapter` are not published: no consumer pins them
yet, and they would add motion pins to the release.

## Compatibility

- **Stage contract:** stays at 2. No stage needs to be reimported.
- **Library API:** unchanged. Sibling ranges stay `>=0.3,<0.4`.
- **Packages:** a library's consumer pins its whole closure: a published library names
  its siblings by version range, not by digest.

## Accepted limitations

- `ost` 0.23.13 cannot declare host packages for a generated consumer, so
  `ost library verify-consumer` covers `mmdPhysicsAdapter` on Windows only.
  `usd-avatar-runtime`'s session lanes build against it on Windows and Linux.
- The limits of the [v0.3.0 record](v0.3.0.md) otherwise stand.
